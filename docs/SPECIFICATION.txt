OBJECTIVE

It will be used on a resume for systems and infrastructure internships (Bloomberg, FAANG, trading firms), so it must be correct, well tested, honestly measured and easy for an interviewer to read and verify.

HARD RULES
- C++20, CMake 3.20+, Ninja. Standard library and POSIX only. No Boost, no third-party code in the core. Everything lives in namespace microfs.
- Must build warning-free with -Wall -Wextra -Wpedantic on GCC and Clang, on Linux and macOS. Do not use -march=native. CPU-specific code (CRC32C hardware instructions, optional SIMD) is selected at compile time or runtime with a portable fallback.
- Complete working code only. No TODOs, stubs or placeholders.
- Honesty: never describe something as lock-free, SIMD, zero-copy, or fast unless the code and a measurement show it. Every number in any document must come from a benchmark run on this machine, produced by a script, with the raw output committed. Never invent or round up figures.
- Comments only where a memory-ordering choice or an on-disk invariant would otherwise be unclear.
- Errors use a Status type. No exceptions across the public API.
- Clean under AddressSanitizer, UndefinedBehaviorSanitizer and ThreadSanitizer.

ENGINE SPEC
1. Memtable: arena-backed skiplist ordered by internal key (user key ascending, sequence descending, type). One serialized writer, lock-free readers using acquire/release atomics. Sequence numbers give snapshot reads. Deletes are tombstones. Memtable size limit is configurable.
2. WAL: 32 KB blocks with fragmented records (full, first, middle, last), each with a CRC32C. CRC32C uses ARMv8 CRC instructions or SSE4.2 when available, with a table-driven software fallback chosen safely at runtime. Sync policy is configurable: every write, every N bytes, or never. Recovery replays until the first corrupt or torn record and truncates the tail. Group commit: concurrent writers are batched behind a leader so one fsync covers many writes.
3. SSTable: 4 KB data blocks (configurable) with prefix compression and restart points, a CRC32C trailer per block, an index block, a filter block, and a fixed footer with a magic number and block handles. Tables are read with mmap, with a pread fallback. A sharded LRU block cache sits in front of data blocks, with hit and miss counters.
4. Bloom filter: MurmurHash3-based double hashing, configurable bits per key (default 10). A prefix filter option lets TickStore skip tables by symbol. Any vectorized probe path must live behind a feature macro with a scalar fallback, and is kept only if the benchmark shows it helps.
5. Versions: MANIFEST log of version edits plus a CURRENT file, updated atomically with write-temp, fsync and rename. Files are tracked per level with smallest and largest keys.
6. Compaction: immutable memtable flushed to L0, then leveled compaction using a k-way merging iterator. Tombstones and shadowed versions are dropped only when no deeper level can contain the key. One background thread, write slowdown and stop thresholds on L0 file count, and snapshot-aware garbage collection.
7. Public API: Open, Close, Put, Get, Delete, Write(WriteBatch), NewIterator (Seek, SeekToFirst, Seek to last, Next, Prev, Valid, key, value), GetSnapshot, ReleaseSnapshot, GetProperty or stats. A LOCK file stops two processes opening one directory. Options struct for every tunable.
8. Env abstraction: a file-system interface used by everything, with a POSIX implementation and a fault-injecting implementation for tests.

TICKSTORE LAYER
- Key encoding: symbol, then big-endian 64-bit nanosecond timestamp, so range scans return one symbol's ticks in time order.
- Value encoding: price (fixed-point integer) and size, with delta and varint encoding of consecutive ticks inside batched records to cut space. Measure the space saving honestly.
- API: AppendTick, AppendBatch, QueryRange(symbol, t0, t1), LastTick(symbol), and a multi-symbol scan.
- A synthetic but realistic tick generator: many symbols, skewed activity, bursty timestamps, random-walk prices, fixed seed.

CORRECTNESS TESTING
- A tiny header-only test harness, no external frameworks. CTest registers every test.
- Unit tests for every component: coding, CRC32C known vectors, skiplist (including concurrent readers during writes), memtable, WAL, block, bloom filter (false positive rate stays under 2 percent at 10 bits per key), table, version edits, compaction.
- Corruption tests: flipped bits and truncated files are detected, never crash.
- Crash-consistency tests using the fault-injecting Env: drop unsynced data, tear the last write at random offsets, and crash during flush, compaction and MANIFEST update. After reopen, every acknowledged synced write must be present and no corrupt state may be observed. Run thousands of randomized crash points with fixed seeds.
- Oracle test: at least 1 million random put, delete, get, scan and snapshot operations compared against std::map, with several close and reopen cycles.
- Concurrency tests run under ThreadSanitizer: multiple readers with a writer, snapshots during compaction.
- Fuzz targets (libFuzzer, built only when the compiler supports it) for the block parser, the WAL reader, the table opener and the batch decoder. Commit a small seed corpus.

BENCHMARKS AND METRICS
Build a reproducible benchmark tool (bench/microfs_bench) with fixed seeds that outputs both a readable table and machine-readable JSON and CSV.
Workloads: fillseq, fillrandom, overwrite, readrandom (hit and miss), readseq, range scan of N keys, mixed read/write at 50/50 and 95/5, multi-threaded reads at 1, 2, 4, 8 threads, WAL sync modes (every write, batched, none), group commit with 1 to 16 writer threads, and the TickStore workload (ingest N million ticks, then range queries, last-tick lookups and multi-symbol scans).
Metrics to report for each run: operations per second, MB per second, latency p50, p90, p99, p99.9 and max (use a self-written HDR-style histogram, not averages), write amplification, read amplification, space amplification, bloom filter probes, filter-saved disk reads and false positive rate, block cache hit rate, compaction bytes read and written, write stall time, WAL fsync count, and TickStore compression ratio.
Experiments to run and chart: bloom filter on versus off for missing-key reads; block cache size sweep; block size sweep; memtable size sweep; bits-per-key versus false positive rate; sync policy versus throughput and p99 latency; reader thread scaling; with and without prefix filter for TickStore.
